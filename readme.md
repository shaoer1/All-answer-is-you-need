#ALL answer is you need全栈智能系统

## 技术栈：Java + Vue3 + 本地部署大模型


## 一、项目概述

本项目是前后端一体化完整闭环的自研AI Agent全栈系统，致力于实现轻量化、私有化、可扩展的智能交互体验。后端基于SpringBoot + Java Agent核心架构，对接本地大模型，实现全链路私有化离线运行；前端采用Vue3 + Vite + Element Plus开发，仿主流聊天软件交互界面，通过Pretext实现打字机流式输出，提升用户交互体验。

系统集成私有RAG知识库检索、全网实时搜索、多工具调度、AI结构化抽取、安全熔断、三层记忆管理等全套核心能力，采用Redis缓存、Milvus向量库替代原有轻量化存储，前端完成会话管理、主题切换等功能开发，支持Docker一键部署，可直接用于毕业设计、校招简历展示、竞赛项目或小型商用场景，具备完整的产品形态和工程落地价值。

## 二、技术栈详情

### 2.1 后端技术栈

- 开发语言：Java 17（推荐版本，兼容11+）

- 核心框架：SpringBoot 3.x

- 大模型部署：Ollama（支持Qwen2-7B、Llama3-7B、GLM4-7B等本地模型）

- 向量检索：Milvus（替代FAISS，支持海量语料管理、分布式部署，提升检索性能）

- 网络通信：HttpClient（用于联网搜索接口调用）

- 缓存机制：Redis（替代内存缓存，用于三层记忆管理、会话存储，支持分布式部署）

- 流式通信：Pretext（GitHub开源项目，用于实现前端打字机效果，基于HTTP长连接单向推送，适配AI问答流式输出场景）

- 部署工具：Docker + Docker Compose（实现一键部署，简化环境配置）

### 2.2 前端技术栈

- 开发框架：Vue3 + Vite

- UI组件库：Element Plus

- 通信方式：Pretext（GitHub开源项目，用于流式通信，对接后端接口，实现实时输出，适配打字机交互效果）

- 依赖管理：npm

### 2.3 核心依赖与工具

- 构建工具：Maven（后端）、Vite（前端）

- 联网搜索：字节跳动火山引擎·智能搜索API

- 工具支持：JSON解析、格式清洗、自动重试、异常拦截等通用工具类

- 数据库工具：MySQL 8.0+（用户隔离、会话存储）、Navicat/DBeaver（数据库管理）

## 三、核心功能清单

### 3.1 AI Agent 核心能力

1. ReAct 完整闭环：实现「思考 → 工具调用 → 观测结果 → 反思校验」全流程自主运行，无需人工干预。

2. 双层决策机制：关键词硬规则兜底+ 本地模型语义判断，确保决策准确性。

3. 双知识库融合：私有RAG离线知识库检索（适配本地语料）+ 全网实时搜索（适配动态时效性内容），智能调度优先级。

4. AI 通用处理能力：自动完成内容去重、摘要压缩、全场景信息结构化JSON抽取（无需硬编码规则，适配赛程、新闻、招聘等多场景）。

5. 小模型工程优化：针对本地7B模型输出不稳定问题，实现JSON格式清洗、解析失败自动重试（默认2次），提升系统稳定性。

### 3.2 工具调度系统（自研工具注册中心）

采用「接口+Map注册+反射调用」架构，解耦工具与Agent核心，支持快速扩展，专注核心工具落地，确保系统轻量化、可稳定运行，具体已实现工具如下：

#### 3.2.1 已实现工具

- 私有知识库检索工具：对接Milvus向量库，实现本地语料精准检索，结合MySQL用户隔离，保障数据安全。

- 全网搜索工具：封装字节跳动火山引擎·智能搜索API，实现全网实时信息检索，支持关键词自动优化、中文语义精准匹配及内容结构化清洗，无需额外开发爬虫。

- AI信息结构化抽取工具：依托本地模型，自动抽取文本关键信息并输出标准JSON。

### 3.3 安全熔断机制

- 最大循环步数限制：默认3步，防止Agent陷入死循环，导致系统卡死。

- 单会话工具调用次数限制：默认5次，避免恶意调用或异常调用导致资源耗尽。

- 异常捕获与熔断：全局异常拦截，工具调用失败时自动降级恢复，不影响整体系统运行。

### 3.4 三层记忆架构

- 短时记忆：基于Redis缓存单轮对话上下文，确保多轮交互连贯，支持会话隔离。

- 工作记忆：基于Redis记录当前任务进度、工具调用日志、搜索关键词，支持任务中断后恢复。

- 长期记忆：通过Milvus向量库存储历史问答经验，结合MySQL用户信息，实现用户隔离，后续同类问题可直接复用，提升响应速度。

### 3.5 前端交互系统

- 交互界面：仿ChatGPT样式，简洁直观，支持多轮对话展示、会话隔离保存，新增会话删除、保存功能。

- 流式输出：通过Pretext（GitHub开源项目）实现服务端单向推送，完成打字机实时渲染回答，提升用户体验。

- 功能对接：完整对接后端所有Agent能力，前端无功能阉割，可直接触发RAG检索、联网搜索、工具调用等操作。


### 3.6 私有RAG知识库用户隔离

- 基于MySQL存储用户信息、会话记录，通过表结构关联用户ID与私有语料，实现用户数据隔离（当前前端暂未实现登录注册，暂通过用户ID手动关联，后续可快速对接登录功能）。

- Milvus向量库中关联用户ID，确保不同用户的私有语料、历史问答数据完全隔离，数据隐私安全。

- 支持用户专属语料上传、管理，仅本人可检索自己的私有知识库内容。

### 3.7 Docker一键部署
- 通过Docker Compose整合后端、前端、MySQL、Redis、Milvus、Ollama所有组件，无需手动配置各个环境。

- 一键启动所有服务，自动完成环境初始化、配置映射、组件联动，简化部署流程，降低环境配置门槛。

- 支持容器化启停、日志查看、版本管理，适配不同部署环境（开发、测试、演示）。

- backend-java：Java后端核心工程，包含Agent核心、工具模块、配置文件、数据库脚本等

## 七、数据库表结构（MySQL，含用户隔离逻辑）


### 7.1 用户表（sys_user）- 用户隔离核心表

核心作用：存储用户基础信息，作为所有用户相关数据的关联核心，实现用户身份区分，是用户隔离的基础。

- 核心字段：id（主键，用户唯一标识）、username（唯一用户名）、password（加密密码，预留）、nickname（昵称）、status（用户状态）

- 隔离关联逻辑：作为父表，通过id字段与会话表、私有语料表、会话消息表建立外键关联，确保所有子表数据均归属具体用户

### 7.2 会话表（chat_session）- 会话隔离表

核心作用：存储用户的聊天会话信息，确保不同用户的会话相互独立，不混淆。

- 核心字段：id（主键）、user_id（外键，关联用户）、session_name（会话名称）、is_delete（删除标记）

- 隔离关联逻辑：通过user_id与sys_user.id关联，查询时仅筛选当前用户的会话，实现会话隔离

### 7.3 会话消息表（chat_message）- 消息隔离表

核心作用：存储会话中的所有消息，确保不同用户、不同会话的消息相互隔离，支持历史记录导出。

- 核心字段：id（主键）、session_id（外键，关联会话）、user_id（外键，关联用户）、message_content（消息内容）、message_type（消息类型）

- 隔离关联逻辑：通过user_id关联用户、session_id关联会话，双重保障消息隔离

### 7.4 私有语料表（user_corpus）- RAG语料隔离表

核心作用：存储用户上传的私有语料，是RAG知识库用户隔离的核心表，确保不同用户的语料仅本人可检索。

- 核心字段：id（主键）、user_id（外键，关联用户）、corpus_content（语料内容）、vector_id（关联Milvus向量ID）

- 隔离关联逻辑：通过user_id关联用户，检索时仅匹配当前用户的语料和向量数据，确保数据隐私

表结构关联总结（核心隔离逻辑）：

1. 所有表均以sys_user.id（用户ID）作为核心关联字段，形成“用户→会话→消息”“用户→私有语料”的关联链路，实现全链路用户隔离；

2. 当前前端暂未实现登录注册，暂通过手动指定user_id的方式关联数据，后续对接登录注册功能后，可直接通过登录态获取user_id，无需手动操作；

3. 外键关联确保数据完整性，删除用户时，其关联的会话、消息、私有语料会自动同步删除；

4. Milvus向量库通过vector_id与user_corpus表关联，间接关联user_id，实现向量检索时的用户隔离。

## 八、启动流程

### 8.1 Docker一键部署
1. 修改配置：打开项目根目录下的 `docker-compose.yml`，替换VOLCENGINE_SEARCH_AK、VOLCENGINE_SEARCH_SK等为个人火山引擎应用配置，可修改MySQL、Redis密码。

2. 启动服务：终端进入项目根目录，执行 `docker-compose up -d`（首次启动自动拉取镜像，耗时稍长）。

3. 验证启动：执行`docker-compose ps`，查看所有容器状态为`Up`即为成功，等待5-10分钟（Ollama模型初始化）。

4. 访问页面：打开浏览器，输入 `http://127.0.0.1:5173`，进入聊天交互界面。

5. 停止服务：终端进入项目根目录，执行`docker-compose down`。
